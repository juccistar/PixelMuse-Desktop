# PixelMuse

**商品视觉创作工作台。** Windows 本地桌面应用，采用 Electron、React、utilityProcess Backend 和 SQLite，涵盖商品素材、规划、生图、编辑分层、套图、模特与花型创作。独立运行，不读取旧 `.env` 或旧 Web 用户数据库，不需要 Redis、BullMQ、Docker 或本地 HTTP 业务服务。

**当前发布版本为0.5.0，已发布到[GitHub Releases](https://github.com/juccistar/pixelmuse-releases/releases/tag/v0.5.0)。** 本版增加参考图驱动自主规划、套图镜头与数量绑定、候选独立调用及跨商品批量创作，保留任务恢复、图片编辑和AI高级设置；旧版本安装包继续保留。 “设置 → 软件更新”连接公开仓库[juccistar/pixelmuse-releases](https://github.com/juccistar/pixelmuse-releases)，提供检查、下载/取消和重启安装；源码与解包运行提供手动下载入口。首次需要手动安装带更新功能的版本，发布步骤与验证边界见[软件更新说明](docs/software-updates.md)。

中断任务可直接重试或结束，项目任务详情支持批量处理；没有核实表单、风险勾选或重试费用确认。保留持久历史、设置草稿保护、编辑会话重读和SKU冲突处理；实际验证范围见[VALIDATION.md](VALIDATION.md)。

商品准备集中上传与配置，图片规划使用卡片和固定检查器，成图与修改支持持久采用、详情顺序和导出记录；参考素材可从规划卡片或检查器打开预览并切换多张；“删除所选”一次处理已勾选需求，受保护或失败项保留选中并提示原因。成图页面显示排队/生成动画，再生成时保留已有图片。单图编辑提交后立即显示版本占位，失败显示黑色缩略图与红色感叹号，成功后替换为真实版本并保留原图。编辑规划明确约束操作与执行方式；非法模型方案显示具体原因，用户主动重试可重新规划并保留历史用量。 图片规划可配置主图与详情画面数，编辑SKU并通过明确确认的图片组共图，独立计算画面数和候选张数；保存规格不会调用模型。九个业务页面、采集、媒体工作空间与七类设置继续沿用用户选定的 A 版黑白界面，保留候选叠放、一行执行摘要和右侧任务详情。全局侧栏支持收起与拖动调宽，工作空间位置仍统一到“设置 → 工作空间与数据”。业务边界见[商品图片规划说明](docs/product-image-planning.md)，维护者从[文档索引](docs/README.md)进入架构、技术栈、来源、目录、设计规范、模块与开发发布流程。

0.4.0 当时通过136文件/1450项全测及Source/EXE各64业务+14采集工作空间+5设置场景；这些属于历史冻结证据。各维护版本实际执行范围与未实测边界单独记录于[VALIDATION.md](VALIDATION.md)，不继承旧版本全测结论。

**0.3.0 已完成原版业务范围的桌面迁移，并通过源码 Electron 与解包 EXE 的完整验收。** 原版九个页面、131 个操作、20 类任务及 Listing 分支均有通过证据。自动验证使用真实本地数据库、图像/ZIP/PSD、Pi 运行时和本机假 Provider；不代表真实模型质量或安装/升级/卸载已验证。各版本证据见 [VALIDATION.md](VALIDATION.md)，完整实施和补修过程保留在 [MIGRATION_STATUS.md](MIGRATION_STATUS.md)。

开发、升级与维护先阅读三份基线文档：[需求与交付标准](docs/requirements.md)、[项目技术栈](docs/technical-stack.md)、[项目当前进度](docs/project-status.md)。专项资料从[维护索引](docs/README.md)进入。

## 开发与启动

要求 Windows x64、Node.js >=22.19.0、pnpm 11.19.0；当前应用使用 Electron 45.2.3。首次安装需要下载依赖和 Electron。

```powershell
cd E:\PixelMuse-Desktop
pnpm install
pnpm dev
```

`pnpm dev` 先构建 Backend 及领域依赖，再启动 Electron 与 renderer 热更新。修改 renderer 以外的包后需要重新启动开发命令。生产源码构建与启动使用：

```powershell
pnpm build
pnpm start
```

首次启动创建独立 userData 和随机主密钥，同一数据目录只允许一个应用实例。生产程序不监听业务 HTTP 端口；开发时 renderer 的 Vite 热更新服务只用于开发。

设置中心采用独立页面，包含常规设置、模型配置、用量统计、工作空间与数据、搜索与采集、软件更新、关于 PixelMuse。模型配置分为模型列表、服务连接、默认用途和高级设置；一组连接复用多个模型，保留模型发现、手动添加、能力和高级协议设置。API Key 仍加密保存，编辑留空保留。全局默认只填充新项目或未配置的工作台，不覆盖已有项目与已冻结任务。各创作页面可通过“管理模型”进入并返回原页面；模特库仍独立管理人物身份。

常规设置保存启动页面、界面缩放、任务通知和创作默认参数；缩放由主进程应用。离开有未保存更改的设置时，可以选择保存、放弃或继续编辑。用量页分别展示请求、任务与当前产物，缺失 Token 标为“未提供”，费用仅按用户单价估算并按币种汇总。价格在请求开始时冻结，修改单价不回改历史；本地重试或回执重放不重复计量。历史回填有数量和字节限制，不承诺完整追溯；删除业务记录后保留最小用量记录，当前产物数量可能减少。CSV 可导出到原生选择的位置，“关于”可导出仅含白名单环境和健康信息的诊断文件。0.4.0 设置中心曾通过源码 Electron 与解包 EXE 各5场景验收，具体证据和边界见 [VALIDATION.md](VALIDATION.md)。

“设置 → 模型配置 → 高级设置”可调整推理请求超时（30–1800 秒，默认 240）、思考强度（自动/关闭/低/中/高，默认自动）、最大输出 Token（512–65536，默认 16384）和同时执行任务数（1–16，默认 2）。推理参数在新任务提交时冻结，旧任务保留原快照及其默认行为；并发上限跨项目影响后续任务认领，降低上限不会取消正在执行的任务。自动思考强度按工作流选择，不支持思考的模型关闭思考。推理连接探测仍使用轻量配置，搜索调用保留独立超时。Pi SDK 随软件更新交付，没有独立 npm 热更新。

内置模板和 1173 套只读套图资源在构建时准备；用户模板、导入/编辑的用户套图存入本地业务库。生产代码不从 `legacy/` 导入运行模块。

## 商品参考图采集

在项目工作台的配置/素材区点击“采集参考图”，输入商品链接并打开独立浏览窗口。可以在网站正常浏览、登录和滚动加载图片，再返回工作台点击“读取当前页图片”，勾选需要的图片并“导入当前项目”。预览经过本地解码，导入保存原图及页面标题、平台、清洗后的商品页链接与采集时间；来源可在项目中查看，关闭采集或重启应用后仍保留。

采集采用通用页面图片、懒加载、分享图及商品结构化元数据读取，适用于正常浏览时可访问的国内外商品页，不保证每个平台、每种登录流程或每张图片都能提取。图片未加载时先在浏览窗口滚动；遇到验证码、网站访问限制、反盗链或不支持的格式时正常处理网站提示，或使用“手动添加图片链接”和原有本地上传。不会绕过网站访问控制，也不会自动向平台发布内容。

采集导入固定为 `STYLE_REFERENCE`，沿用项目参考图数量、文件容量和图片解码限制；重复内容复用已有资产，不改变它的角色或覆盖原来源。商品标题等来源信息不会自动变成已核验事实，采集参考不能替代当前项目的 `PRODUCT_TRUTH`。

浏览窗口与应用使用不同的非持久会话，不提供应用 preload、Node 或文件能力。“清除本次登录”会清除会话并关闭本次采集；普通关闭也清理该会话。Cookie 和签名图片地址仅在宿主内短期使用，不写入项目来源或媒体工作空间。网页导航后旧候选失效，需要重新读取。取消时已提交的导入仍以项目素材与来源查询为准。

## 本地工作空间

从“设置 → 工作空间与数据”查看当前素材目录，这是唯一的工作空间位置配置入口。点击“选择工作空间目录”后，通过系统目录选择器选择父文件夹，应用在其下创建专属 `PixelMuse` 子目录；已有同名目录会拒绝接管。首次设置前，媒体继续使用原应用数据目录，旧项目仍可正常打开。

切换会先复制已有受管文件，逐文件校验后再保存配置并重启 Backend。进度显示文件数与字节数；复制阶段可以取消，失败时保留原素材。活动或排队任务未结束时拒绝切换；已经接受的上传、查询写入及其他后台操作先等待结束，不通过取消生成任务来迁移。源目录保留为旧副本，后续修改只写入新空间，不会双向同步。

上传、采集、生成、编辑、分层、模特、花型、草稿、印刷包、缩略图及受管导出使用相同的媒体根目录。客户端画布生成的 PNG/PSD/ZIP/JSON 在打开“另存为”对话框前先归档到 `exports/canvas/`，取消外部另存仍保留归档。用户另存到其他位置的是额外副本。

项目记录、服务连接与模型设置、SQLite 和系统保护的主密钥仍保存在原 userData；素材目录不携带这些凭据和业务库。备份前退出应用，并同时备份完整 userData 与当前媒体工作空间。仅复制素材目录不能恢复项目记录或跨设备解密凭据。外置设备失联时会停止素材读写，需重新连接原路径、原身份的工作空间，不会偷偷改用旧副本或创建空白替身。

## 从项目到成图

1. 首次使用先在“设置 → 模型配置”添加服务连接及有效的推理、生图模型，再创建项目。默认用途用于新项目；模型发现和连接检查不能代替实际生成质量验证。
2. 在“商品准备”左侧上传商品图和参考图，右侧填写商品信息、主图/详情需求并管理 SKU。SKU 图片数由参与规格与显式共图目录计算。事实、禁止宣称、市场、双语言、保护模式、模型、分辨率、候选数、联网研究和 AI 帮写继续保留；折叠不会清除输入。
3. 选择“模型自主规划”或“套图批量规划”，点击“AI 一键规划”。自主模式直接读取商品图和参考图，不要求人工品类或模板分类；套图模式采用明确镜头清单，并由镜头用途派生数量。每个画面只规划一份提示词，候选数只控制后续独立生图次数。提交前等待配置保存，商品真值和SKU附件保持隔离；规划不会自动生成图片。首页“套图批量创作”可为多个已有商品分别规划，检查后再明确确认生图。
4. 在“图片规划”按主图/SKU/详情筛选方案，点击卡片在右侧检查器查看引用素材、编辑画面要求和生成参数。商品事实或附件变更会使受影响的未成图规划过期；可更新受影响方案或重做整套方案。取消需求保留其他目标编号。勾选画面后点击“确认并生成”，过期或不完整规划会拒绝执行。
5. 在“成图与修改”切换候选、采用、重新生成、下载或进入单图编辑。采用状态与下载勾选独立，采用和详情顺序可在重开后恢复；失败、已中断和未生成目标保留位置。单图修改创建独立版本并保留原图，输入变化会阻止确认旧方案；继续遵守原有审批和自动续接规则。
6. 下载已采用图片或手动勾选输出，导出 ZIP、详情长图与切片。导出记录可恢复已完成文件入口，保存仍通过原生对话框。长图使用已有输出本地排版与重采样。任务摘要与任务详情保留，未知外部结果不能通过重新规划或再生成绕过。

商品描述和补充说明的 AI 帮写沿用单任务流程。商品描述帮写排队或运行时不能提交补充说明帮写；后者提交前还会等待保存并保存尚未提交的商品描述。重新打开页面不会自动应用旧帮写结果。

新版自主／套图规划均要求实际商品图和支持视觉的推理模型；有参考图时会选择并在生图时实际附加，不能仅用文件名或文字替代看图。SKU只使用用户为该目标明确选择的本项目商品图。`PIXEL_PROTECTED` 对远端整图生成提供真值输入与保真提示，**不保证远端返回图逐像素不变**；明确旧模板来源仍遵守其原有能力边界。

搜索来源可配置启用状态与优先级，供支持研究工具的工作流使用，并保存来源审计；搜索结果不能新增未经核实的商品事实。新版自主／套图规划直接基于所给图片完成首轮，不额外增加分类或检索模型调用。保存配置本身不调用生成模型；提交推理、生成、选角、分割等任务可能产生服务费用，部分工作流包含多轮调用。

## 编辑与分层

从已有输出进入编辑工作区，选择当前分支和基图，填写编辑目标、添加项目/临时参考、绘制编辑蒙版与保护蒙版，或设置扩图边距。会话读取失败时可重读或重新打开，不把失败当成空会话。编辑任务中断时可在编辑器内直接重试或结束，无需填表或确认费用。编辑回合保留父图、根图、候选、引用和分支记忆。缺少目标、参考或画布条件时显示 `NEED_INPUT`；需要确认的方案进入 `AWAITING_CONFIRMATION`，确认后才生成。无需确认的方案由持久化结算创建后续生成任务。

像素保证取决于实际合成方式：硬蒙版局部编辑在本地保留有效选区外的源 RGBA；保护蒙版参与扣除可编辑区；自然融合会影响选区边缘的过渡带；扩图把原画布 RGBA 回贴到对应位置。无蒙版整图改绘及普通远端生图没有相同的本地像素保证。编辑/保护蒙版必须为 PNG，尺寸不匹配直接拒绝。

分层面板支持视觉模型自动识别元素、人工文本/画框提示，再调用 SAM 类分割或 Seedream 图层拆分。识别或导出中断时，面板内提供直接重试和结束，操作后重新读取结果，保留已有成图与成功导出。框提示是否可用取决于协议，Gitee SAM3 不支持框提示。人工画框是用户指定选区，不能称为自动识别；画框后调用分割模型仍可能计费。

元素层使用原图 RGB，alpha 为源图 alpha 与模型选区相乘；空选区、缺失元素或不支持的协议会失败。Seedream 的补绘背景含生成内容，不能承诺与原背景像素相同。挖空背景与软边元素叠加也不保证完全还原原图。Backend 可生成真实 PNG 图层和 PSD；用户还可在图层编排中调整显隐、顺序，并本地另存合成 PNG、图层 ZIP 或 worker 编码的 PSD。编排只影响本次预览与导出。

Pi 是这些规划、文案、编辑方案、元素识别和套图反推中的嵌入式工作流，不另设通用聊天代理或任意 shell/文件工具。

## 模特、花型与草稿

模特库保存身份规格和参考脸，选角生成多张定妆候选后人工选定。替换参考脸创建新的内容身份，已提交任务仍引用原来的字节；它与 Provider 的模型配置是两种不同对象。

花型可直接上传、主题起稿，或从来源图片提取。SAM 分割提取只取源像素并应用 alpha；生成式摊平提取会重绘。改色创建衍生花型，生成式变体保留父来源，验缝记录算法证据。印刷规格包按尺寸/DPI、本地排版和重复排列生成图稿、重复单元、示意图及 manifest；放大涉及重采样，不宣称无损放大。Listing 生成 Etsy、Amazon、TikTok Shop 的结构化文案并校验相应字段约束，不自动向平台发布。

未定稿创作在草稿工作台中保存。自动保存使用 revision 比较更新，离开前刷新待保存内容；冲突需要刷新处理。每批任务保留稳定槽位与候选，可继续整图/笔迹改稿、定向接缝编辑、SAM 去底、本地改色和验缝。只有明确选择定稿入库，候选才进入正式花型库；失败槽位可按安全条件补偿，成功和未知槽位不能当作失败重做。

成包流水线持久化来源、验缝、印刷包、Listing 步骤。接缝风险会停在 `AWAITING_INPUT / SEAM_RISK` 等待人工裁决；未知外部结果停在 `EXTERNAL_RESULT_UNKNOWN`，不能用“重跑”绕过。这些聚合已通过本机假 Provider 下的完整 Electron 与解包 EXE 端到端验证。

## 输入和容量

导入支持 PNG、JPEG、WebP、AVIF、TIFF，按文件头、实际解码和像素容量验证，SVG 不在导入契约中。下面的限制按入口分别生效。

| 入口/用途 | 当前限制 |
| --- | --- |
| 普通文件转字节及 Backend 普通图片上传 | 单图 50 MiB；具体业务入口可更严格。 |
| 套图反推界面 | 最多 12 张来源图，单图 30 MiB；目标套图为 5–12 镜。 |
| 原生图片选择能力 | `maxFiles` 可设 1–32，默认单选 1、多选 32；单图 50 MiB，本次合计 128 MiB。并非所有拖放/画布入口都经过此选择器。 |
| 字节传输契约/画布 Blob | 单份 64 MiB；这不扩大文件上传的业务上限。 |
| 图片检查 | 存储默认最多 100,000,000 解码像素；先限字节和像素，再遍历全部页面解码，拒绝只读头正常但像素损坏的文件。原生解码中的取消会等待有界计算结束。 |
| 项目素材与视觉规划 | 商品图最多 6 张，其他参考合计最多 6 张；规划/文案按此选择输入。 |
| 普通分镜生成 | 引用中的非商品参考最多 4 张；商品真值单独计数，像素保护带入当前项目商品图，不能解读成总附件最多 4 张。 |
| 候选与图数 | 分镜、编辑、选角、花型起稿/变体、草稿单批候选各为1–4；原AI规划单次目标1–12镜，候选数独立于项目画面数。 |
| 商品图片规划 | 最多60个SKU、60个显式组；主图0–12、详情0–24、每SKU组1–4个画面；提交合计最多96画面，一个PLAN内部每批最多12画面。 |
| 草稿媒体 | 参考最多 6 张，笔迹媒体另限 24 张。 |
| 分层元素 | fal / Grounded-SAM / Gitee SAM3 最多 32 个，Seedream 最多 16 个；框提示仍受协议能力限制。 |

剪贴板文本能力有 65,536 字符上限（当前界面文案称“64 KiB”）。画布/模板等客户端生成文件的原生保存能力限 64 MiB，支持 PNG、PSD、ZIP、JSON 并校验签名/扩展名；它与引用已有 Backend 资源再复制保存的能力不同，不能据此前者给全部 ZIP/PSD 资源导出设同一上限。

## 任务、取消与恢复

SQLite 是任务状态真相，全局任务并发默认上限为 2，可在模型高级设置中调整。提交时冻结实际项目、事实、模型/能力、素材哈希、模板和有效参数，执行使用原快照。重复提交依据实际业务意图去重；状态、执行时间和已编译提示等运行字段不能把同一生成变成新付费意图，特殊 `revision='retry'` 标记也不能绕过已有成功或未知结果。RPC 超时后应重新查询，不能据超时判断没有提交。

每个模型轮次、候选、分割元素和搜索调用分别记录稳定请求键。真正发送前持久化 `IN_FLIGHT`，完整响应读到 EOF 后加密保存回执；SSE 的观察进度可以实时显示，此时仍未证明请求已完成。任务成功、执行工具或进入下一付费轮次必须等待完整回执落库。

调用已经发出却没有完整回执时，断线、取消或崩溃会保守进入 `UNKNOWN`，界面显示“已中断”，不会自动重发。用户可直接点击任务的“重试”或“结束”，项目任务详情也可批量处理，不需要逐请求核实、填写依据或确认费用。后台将同一任务的未完成请求整体归档，仍保留 `UNKNOWN` 事实，并记录任务操作和执行代次；重试复用冻结输入、可靠回执及已有成功结果，实际新请求独立计量；结束不发送请求。旧无回执用量仍保持未知，不虚构 Token 或费用。Listing 历史和模特入口可跨重启定位中断任务；只读历史、损坏快照与过期领域关联不能通过重试绕过。

可靠完整回执的本地恢复仅支持独立的 PLAN、COPYWRITE、GENERATE、SUITE_FORGE、MODEL_CAST，拒绝流水线任务。恢复只重放已有回执，不新增模型请求；缺少后续所需回执时失败并保留数据。

已提交的部分候选或产物会保留，任务整体失败或取消不把它们改回失败。恢复和显式补偿按槽位/候选身份查找已成功结果；旧运行代次的迟到写入受到校验，不能覆盖新分支或推进已经替换的流水线步骤。文件存在本身不等于业务成功。

## 数据、升级与备份

品牌升级继续固定使用 `<appData>/EcomGen` 作为 Electron userData，避免改名后丢失项目和 safeStorage 主密钥。隔离预览或测试可在启动前把 `ECOMGEN_DESKTOP_DATA_DIR` 设为绝对目录，覆盖整个 userData。媒体默认与数据库同根；设置独立工作空间后媒体根变为所选父目录下的 `PixelMuse/`。

```text
<userData>/
  master-key.enc        safeStorage 保护的随机主密钥
  logs/main.log         固定生命周期诊断
  data/
    backend.sqlite      唯一业务库，0.5.0为schema v12（0.4.8为v11）
    backend.lock        Backend owner 锁
    workspace-owner.json / workspace-config.json / workspace-migration.json
    assets/ outputs/ edits/ layers/ exports/   # 未设置独立空间时的默认媒体根
    models/ patterns/ drafts/ print-packs/ suite-forge/ thumbs/ tmp/

<所选父目录>/PixelMuse/                      # 设置后的独立媒体根
  .pixelmuse-workspace.json
  assets/ outputs/ edits/ layers/ exports/
  models/ patterns/ drafts/ print-packs/ suite-forge/ thumbs/ tmp/ suites/
```

媒体根的父目录还会出现按路径隔离的临时 `.pixelmuse-storage-<路径哈希>-<pid>-<uuid>.claim` 所有权文件，正常退出后释放。所有权位于被保护目录之外，使取消或中断恢复清理不会提前释放正在删除的目录。

首次用0.5.0打开旧桌面v1–v11数据时，在事务内升级到canonical v12，保留项目、服务连接密文、素材、分镜、输出和请求/任务历史。v1/v2旧任务只读，不再执行或普通重试；旧结果以安全文本和可用资源展示，不伪造成新Output/Pattern。v3/v4补齐采集来源、应用设置、模型单价及请求用量表；v5→v6保留有效用量恢复游标；v6→v7新增SKU目录和分镜用途/过期/替代字段；v7→v8新增项目采用状态与详情顺序，导出记录继续复用原持久任务；v8→v9替换 UNKNOWN 审计触发器；v9→v10加入任务级中断处置约束，保留旧核实记录、回执和密文；v10→v11为应用设置补入AI默认值；v11→v12增加规划来源、跨商品批次及共享修订结果，均不改写旧任务快照和回执。没有历史SKU证据的项目保持空目录，旧图不补造归属。数据库升级不移动旧平铺文件；用户随后选择工作空间时会按受管引用复制并校验。缺失或变更的历史文件显示不可用；旧ZIP/PSD原来没有哈希，首次登记现存文件后才固定校验和，不能据此证明登记前从未被替换。

不导入旧Web数据库，也不解释v1/v2旧运行载荷继续执行。升级到v12后，不使用0.4.8或更旧安装包打开同一数据目录；升级前退出应用并备份**整个userData和已配置的媒体工作空间**，不要只复制SQLite，运行时还可能存在WAL/SHM。

Provider/搜索凭据使用 AES-256-GCM 加密，随机 32 字节主密钥由系统 safeStorage 保护，只在 main 与 Backend 内部使用。公开界面只显示是否已配置 Key，不回传密钥、密文或完整执行快照。safeStorage 受 Windows 账户/设备环境约束，复制整目录也不保证跨账户/设备可解密，当前没有可移植密钥导出工具。不要把旧 `.env`、凭据或旧 Web 用户数据库复制到新版。

界面使用系统无衬线字体，等宽文字优先使用本机 JetBrains Mono，缺失时回退 Consolas 等系统字体；仓库没有随附字体二进制，也不依赖在线字体。许可证清理范围仅为已明确授权的 7 份自有许可证及自有 MIT 元数据；第三方依赖声明与上游来源记录仍保留。

## 验证与发布

在 desktop 根目录运行：

```powershell
pnpm build
pnpm test --maxWorkers=1
pnpm test:e2e:check
pnpm test:e2e:mock
pnpm test:e2e:pixelmuse
pnpm test:e2e:settings
pnpm test:release-checker
```

`test:e2e:check` 只核对场景和操作覆盖；`test:e2e:mock` 才驱动真实 Electron、隔离 userData 和本机假 Provider。`test:e2e:pixelmuse` 驱动品牌升级、工作空间和采集的 14 个新功能场景，默认需要本机 `release/0.3.0/win-unpacked/EcomGen.exe`，也可通过 `PIXELMUSE_BASELINE_EXECUTABLE` 指定已发布 0.3.0 EXE；基线缺失会失败，不会跳过升级检查。`test:e2e:settings` 验证原生边界、模型配置、持久偏好、用量和实际设置页面操作，共5场景。全量测试与 Electron 验收应分开运行，避免图像处理和磁盘争用导致时限耗尽。
