# PixelMuse 产品需求与交付标准

- 基线：2026-11-12公开发布版本0.5.0，包含参考驱动自主规划、套图数量绑定和跨商品批次需求；实际交付与验证范围以项目进度及验证记录为准。
- 读者：产品、开发、测试、发布与维护人员。本文定义目标、范围和可观察的交付要求，不替代通信契约或实际验证证据。
- 技术与依赖见[技术栈](technical-stack.md)；实际进度见[项目当前进度](project-status.md)；具体版本的检查、证据和未验证边界见[验证记录](../VALIDATION.md)。

## 产品目标

PixelMuse 是 Windows x64 本地桌面“商品视觉创作工作台”。用户以商品图和参考图为起点，配置商品信息和图片需求，通过 AI 一键规划形成可审阅方案，明确选择并确认生图，再逐图编辑、采用、排序和导出。项目数据、媒体和长任务应可在本地持续管理；外部模型或搜索服务按用户配置调用。

产品还支持商品参考图采集、资产与套图复用、人物模特、花型和未定稿创作，使用户能够在同一工作环境内完成相关素材制作。采集来源、创意参考、模型建议与用户确认的商品事实必须区分。

### 使用者与任务

以下角色根据现有功能归纳，并非对用户组织结构的限定。

| 推定使用者 | 主要任务 |
| --- | --- |
| 商品运营或视觉创作者 | 准备商品资料、规划多用途图片、选择生成结果并导出。 |
| 素材设计者 | 制作套图、模特、花型或草稿，并将确认的素材用于创作。 |
| 工作台管理员或维护者 | 配置服务与工作空间，查看用量、处理任务中断、备份和更新应用。 |

## 范围和边界

- 范围包括项目、工作台、资产库、套图工坊、模特库、花型库与工作区、草稿列表与工作台、参考图采集、媒体工作空间以及七类设置。
- 不恢复旧版 HTTP、Redis、BullMQ、SSE 业务运行兼容；旧版仅为迁移参考，不读取其 `.env`、凭据或 Web 用户数据库作为新版运行依赖。
- 不提供通用聊天代理、任意 shell 或文件工具；内嵌智能工作流服务于具体业务。
- 不自动向电商平台发布内容；Listing 是结构化文案产出。
- 不绕过网页访问控制，也不保证所有网站、登录流程或图片均可采集。
- 不把人工框选称为视觉模型自动识别，不把远端整图生成的保真提示称为逐像素保证。

## 功能需求与验收标准

需求 ID 稳定，用于关联变更、测试与证据；调整或废弃时保留 ID 和变更说明。详细交互与数据语义分别见[模块地图](modules.md)、[商品图片规划](product-image-planning.md)和[设计规范](design-system.md)。

### 项目与商品图片

| ID | 需求与可观察的验收标准 |
| --- | --- |
| REQ-PROJ-01 | 项目画廊支持创建、编辑、归档、恢复及永久删除项目，并可进入对应工作台；重开后状态与持久记录一致。 |
| REQ-PROJ-02 | 工作台提供商品准备、图片规划、成图与修改三个阶段；商品信息、事实、禁止宣称、市场、素材角色、模型和生成参数可配置并保存。 |
| REQ-PROJ-03 | 主图、SKU图、详情图按实际配置计算画面数；每画面只规划一份提示词。候选数仅由本地调度控制相同提示词的独立图片模型调用次数，每次1张，不进入模型提示词或输出要求。SKU支持属性、编码、参与状态和本项目商品图引用。 |
| REQ-PROJ-04 | SKU 编辑、复制、组合及图片组先形成草稿；只有用户明确确认的组才共图。保存采用版本校验和原子提交；冲突不覆盖已有数据，保留草稿供对照或明确放弃后重新载入。 |
| REQ-PROJ-05 | 主流程支持参考图驱动的模型自主规划和套图批量规划，在提交前等待配置保存；自主规划不依赖人工品类或模板分类，商品图决定身份、参考图引导视觉。保存SKU或数量本身不调用模型，规划后由用户审阅并明确确认才生图。 |
| REQ-PROJ-06 | 分镜显示用途、实际引用、画面要求与生成设置，可筛选、编辑和选择；不完整、过期或替代的分镜不能进入新生成。批量删除对受保护或失败项保留选择并说明原因。 |
| REQ-PROJ-07 | 商品或 SKU 变化只使受影响的未成图规划待更新；已提交任务使用冻结输入，历史分镜和成图保留原身份及用途快照，不按当前目录重新标记。 |
| REQ-PROJ-08 | 成图支持多候选查看、持久采用、重新生成、下载、单图编辑及详情排序；浏览、采用和下载勾选互不混淆，重开后采用状态和详情顺序可恢复。 |
| REQ-PROJ-09 | 支持导出采用或明确勾选的输出，提供 ZIP、详情长图及切片和导出历史；导出对应实际冻结的输出集合，另存使用原生选择器。 |
| REQ-PROJ-10 | 商品描述和补充说明 AI 帮写使用单任务流程：前者提交、排队、运行及结果采用/保存期间阻止提交后者；后者提交前等待保存并保存未提交的商品描述，保存失败不能使用旧描述继续提交。重新打开页面不自动应用旧结果。 |
| REQ-PROJ-11 | 图片规划卡片和检查器中的参考素材可点击预览并切换多图；打开预览不改变画面勾选。删除所选只移除允许删除的目标，其他画面和已成功产物保持原身份。 |

### 编辑、素材与创作

| ID | 需求与可观察的验收标准 |
| --- | --- |
| REQ-EDIT-01 | 单图编辑基于已有输出，支持目标、参考图、编辑/保护蒙版和扩图；编辑结果形成独立版本并保留原图，输入变化不能确认旧方案。缺少输入或需要确认时明确显示并等待用户操作。 |
| REQ-EDIT-02 | 硬蒙版局部编辑保留有效选区外的源 RGBA，保护蒙版扣除可编辑区域；自然融合边缘与无蒙版整图改绘按实际方式表述，不声称相同保证。尺寸不符或非法蒙版被拒绝。 |
| REQ-EDIT-03 | 分层明确区分视觉模型识别、用户文字或矩形提示、模型分割和生成式拆层；协议不支持或选区无效时说明失败。支持实际图层的预览、编排和 PNG、ZIP、PSD 导出。 |
| REQ-ASSET-01 | 资产库支持按类型筛选、分页、预览和保存，并按资产类型提供复制到项目的操作。 |
| REQ-SUITE-01 | 套图工坊支持来源图反推和满意规划抽象为可复用草稿，检查并明确确认后入库；商品专属事实和SKU绑定须抽离，原成图只能作为参考。 |
| REQ-SUITE-02 | 套图镜头清单绑定主图、详情及每SKU组数量，改数量同步增删镜头并保留其他镜头身份；每款商品分别看图适配，套图版本冻结到任务。 |
| REQ-SUITE-03 | 同款／同类商品可组成批次，共享明确选择的套图和参考，各商品事实、商品图与任务隔离。逐商品展示进度与错误，明确确认生图，保留部分成功和重开查询，不自动推进后续付费阶段。 |
| REQ-MODEL-01 | 模特库管理人物身份与参考脸，生成定妆候选并由用户选定或删除；更换参考脸不改变已提交任务的素材字节。人物模特与服务模型配置分开。 |
| REQ-PAT-01 | 花型支持上传、分割或生成式提取、主题起稿、正式库浏览、本地改色、生成变体和验缝；来源关系及不同提取方式的像素语义可辨识。 |
| REQ-PAT-02 | 花型工作区支持印刷规格包、示意图、结构化 Listing 和成包流水线；接缝风险等待人工处理，未知外部结果不得借重跑绕过。重采样不表述为无损放大。 |
| REQ-DRAFT-01 | 未定稿创作支持创建、归档、恢复、删除、自动保存、参考图、批次/槽位/候选、笔迹或接缝改稿、去底、改色、验缝和比较；明确选择定稿后才进入正式花型库。 |
| REQ-DRAFT-02 | 草稿自动保存采用版本比较，离开前刷新待保存内容；冲突提示处理，成功与未知槽位不能作为失败槽位重做。 |

### 采集、设置和更新

| ID | 需求与可观察的验收标准 |
| --- | --- |
| REQ-COLL-01 | 用户可在独立浏览窗口访问商品页、读取当前页图片、选择并导入项目；也可手动添加图片链接或本地上传。来源记录保留清洗后的页面信息和采集时间。 |
| REQ-COLL-02 | 导入采集图固定为 `STYLE_REFERENCE`；重复内容复用时不改变已有角色或覆盖来源。网页导航后旧候选失效；关闭或清除本次登录后清理独立非持久会话。 |
| REQ-SET-01 | 设置中心提供常规设置、模型配置、用量统计、工作空间与数据、搜索与采集、软件更新、关于 PixelMuse 七类入口。未保存设置离开时可保存、放弃或继续编辑。 |
| REQ-SET-02 | 模型配置支持服务连接、模型发现或手动添加、能力、默认用途和高级参数；Key 编辑留空保留原值。默认值只填充新项目或未配置字段，不覆盖已有项目或冻结任务。 |
| REQ-SET-03 | 用量分别展示请求、任务和当前产物；缺失 Token 明示未提供，费用按请求开始时冻结的用户单价估算并按币种区分，不冒充服务商账单。支持 CSV 与白名单诊断导出。 |
| REQ-SET-04 | 搜索源可配置启用状态和优先级；视觉研究保留来源审计，搜索结果不能自动增加未经核实的商品事实。 |
| REQ-SET-05 | 模型高级设置提供推理请求超时、思考强度、最大输出 Token 和全局任务并发；保存后重启仍有效。推理参数只影响新提交任务，旧任务沿用冻结参数；降低并发不取消在途任务，维护暂停期间不得因修改并发恢复认领。 |
| REQ-UPD-01 | 软件更新固定使用公开稳定发布仓库 [juccistar/pixelmuse-releases](https://github.com/juccistar/pixelmuse-releases)；提供检查、下载、取消和重启安装状态，源码及解包运行提供手动下载入口。 |
| REQ-UPD-02 | 启动检查不自动下载或在普通退出时安装；任务繁忙、工作空间迁移或 Backend 未安全关闭时拒绝安装并保留可理解的反馈。Pi 随应用更新交付，不提供独立 npm 热更新。 |

高级设置的当前基线如下，取值需与[设置契约](../packages/contracts/src/settings.ts)一致：

| 参数 | 取值范围 | 默认值 |
| --- | --- | --- |
| 推理请求超时 | 30–1800 秒 | 240 秒 |
| 思考强度 | 自动、关闭、低、中、高 | 自动，遵守工作流和模型能力 |
| 最大输出 Token | 512–65536 | 16384 |
| 同时执行任务数 | 1–16，跨项目共享 | 2 |

推理参数适用于规划、文案、编辑方案等推理工作流；连接探测和搜索保留各自的轻量配置与超时。全局并发表示持久队列的同时执行任务数，各 Provider 的服务限制仍需遵守。

## 跨功能不变量

| ID | 需求与可观察的验收标准 |
| --- | --- |
| REQ-TRUTH-01 | `PRODUCT_TRUTH` 是用户明确指定的本项目商品真值；采集图、来源标题、搜索结果及模型建议不能自动成为真值或已核实事实。SKU 商品图引用必须属于当前项目且为图像类型的商品真值。 |
| REQ-TRUTH-02 | `PIXEL_PROTECTED` 要求本项目商品真值和支持图片参考的模板，并实际向图片模型提供相应真值；SKU 使用该目标明确选择的真值子集。普通远端整图返回不保证逐像素不变。 |
| REQ-JOB-01 | 长任务持久化，提交时冻结事实、素材身份、模型能力、模板及有效参数；后续配置变化不改写已提交任务。业务状态以查询结果为准，事件仅触发重新查询。 |
| REQ-JOB-02 | 使用稳定业务意图指纹和外部请求身份去重；更换目录版本、分镜身份或重生成键不能绕过活动或未知请求屏障。提交超时后先查询，不推断未提交。 |
| REQ-JOB-03 | 外部请求发出而缺少完整可靠回执时保留 `UNKNOWN`，界面显示“已中断”，不自动重发。用户可直接重试或结束，项目任务详情支持批量；不要求核实表单、风险勾选或重试费用确认。 |
| REQ-JOB-04 | 重试沿用冻结输入、可靠回执和已有成功结果，保留未知事实及操作历史；新外部请求单独计量，结束不发送请求。只读历史、损坏快照和过期领域关联仍受保护。 |
| REQ-JOB-05 | 成功的部分候选和产物不因整体失败或取消被抹除；恢复按稳定身份处理，迟到结果不能覆盖新执行代次。文件存在本身不等于业务成功。 |
| REQ-DATA-01 | SQLite 业务记录与系统保护的主密钥保留在原 userData；独立媒体工作空间只承载受管媒体，不作为业务库或凭据备份。备份要求退出应用并同时备份完整 userData 和当前媒体空间。 |
| REQ-DATA-02 | 工作空间位置仅在“设置 → 工作空间与数据”配置；切换复制并逐文件校验后才切换配置，支持进度和复制阶段取消。活动或排队任务存在时拒绝迁移，失败保留原素材。 |
| REQ-DATA-03 | 媒体空间失联时停止素材读写，提示重连原路径及身份，不静默切换旧副本或创建空白替身；原副本与新空间不自动双向同步。 |
| REQ-SEC-01 | Provider 与搜索 Key 加密保存，随机主密钥由系统保护；公开界面只显示配置状态，不回传、记录或导出凭据。不得提交真实凭据、用户数据库、用户素材和安装包。 |
| REQ-SEC-02 | renderer 通过白名单契约访问能力，不直接访问 Node、数据库、Provider 或任意本地路径；采集窗口使用隔离会话，不取得应用 preload 或文件能力。 |
| REQ-UI-01 | 界面沿用选定的黑白极简方向，真实商品色彩和蒙版语义不变；加载、空、失败、不可用、成功及中断状态可区分，状态不能仅靠颜色传达。 |
| REQ-UI-02 | 保留键盘焦点、明确标签和减少动态效果支持；保存失败保留用户输入，隐藏业务页面不能留下可交互的抽屉或抢占快捷键。 |
| REQ-UI-03 | 排队/生成显示动态反馈，再生成保留已有图片；编辑提交在等待 IPC 回执前立即出现版本占位并防止重复提交。失败占位为黑色缩略图、红色感叹号及可理解提示，成功后由真实输出替换，不伪造产物。 |

## 交付与验收定义

每次交付按变更范围记录下列结果，并关联需求 ID 与证据；没有执行的项目标明未验证，不沿用其他版本的结果。

1. **实现与兼容**：代码和契约满足相关需求，数据迁移、用户数据保护及任务不变量有明确处理；同步更新受影响的文档。
2. **范围化验证**：执行与改动相称的构建、自动化及真实 Electron 界面/操作验证；涉及持久队列、取消、重试、重启恢复或 IPC 边界时验证真实行为。记录环境、范围、结果和限制。
3. **发布产物**：需要交付安装包时，核对待发布版本、构建、解包程序、安装器及更新元数据的一致性，并将运行与内容检查证据绑定到实际候选。静态内容比对不能代替实际安装运行。
4. **独立验证边界**：真实模型质量、远端可用性和计费，以及已安装版本的安装、覆盖升级和卸载须分别实际验证；假 Provider、源码窗口和解包 EXE 不证明这些结果。
5. **来源与分发**：源码仓库与公开二进制发布仓库分离；仅发布经授权的文件。Electron 安装包中的编译 JavaScript 可被提取，打包不保证客户端实现保密。

交付状态和本次实际验证以[项目当前进度](project-status.md)与[验证记录](../VALIDATION.md)为准；发布和更新步骤见[软件更新说明](software-updates.md)。

## 维护规则

- 产品负责人负责确认目标、范围及验收变化；开发维护者负责同步实现、需求 ID、关联文档和验证证据。角色为职责划分，可由同一人承担。
- 变更需求时记录原因、影响范围和验收方式；已废弃 ID 标为废弃，不复用。实际完成与未完成事项放在进度文档，验证证据放在验证记录。
- 契约以 `packages/contracts` 的 TypeBox schema 为手写真相源；文档与实现不一致时先核实预期与实际行为，再同步修订，不凭历史验收推定当前行为。
