# 项目模块主流程重构方案

日期：2026-11-07

状态：本轮源码重构的设计依据。2026-11-07 按用户“复用已有配置、上下文组织与 AI 调用方案”的要求修订，随后按用户选定的四图实施。本文保留目标方案，具体落地行为与边界以 README、页面设计稿的落实说明和 VALIDATION 为准；已发布0.4.5安装包不包含本次源码改动。

## 重构原则

本次采用增量整理：复用当前配置语义、上下文构建、模型协议、持久任务与编辑链，重构用户入口、草稿生命周期、方案有效性和结果组织。界面收起某项配置不代表删除它；统一按钮不代表把不同规划策略改成一个通用 Prompt。

实施前建立“现有配置字段 → 保存位置 → 上下文消费者 → 新界面位置”的映射，以及 AI、自选模板、套图、商品目标规划、单图编辑的能力清单。每项能力必须有复用、适配或明确缺陷修复的归属，不允许因组件重写遗漏。

保留现有高级功能和有效数据。只清理已被新入口接管、且没有独立业务职责的重复交互及失效状态；不按文件大小、新旧命名或页面是否显示来判断是否删除。

## 复用清单与必要适配

以下依据当前源码核对。保留某个模块是保留其职责和执行语义，必要时仍需增量扩展输入契约，不承诺相关文件一行不改。

| 现有能力 | 决策 | 本轮改动边界 |
| --- | --- | --- |
| 项目模型、候选数、分辨率、比例、市场、文案/提示词语言、保护模式、联网研究等配置 | 复用字段、默认值、校验和保存逻辑 | 整理展示位置，补统一保存完成屏障；沿用各调用的覆盖优先级 |
| 描述、已核验事实、禁止宣称、品牌指南等上下文 | 保留现有结构与消费者 | 统一两个入口的有效输入，补来源版本及过期判断 |
| AI 帮写、手选类型、用户模板、套图选择、历史配置套用 | 保留能力 | 共用补充说明草稿；套图选择有临时草稿和取消回滚 |
| 规划 Agent、模板知识工具、平台指引、提示词契约、校验与修复 | 复用 | 仅为目标身份和显式模板约束增加适配，不另写简化版通用 Prompt |
| 素材角色、P/R 句柄、视觉附件、压缩缓存、商品图子集 | 复用 | 新入口传递同样的结构和真实附件；SKU 隔离仍由后端保证 |
| 商品目标分批、整套风格锁、完整结果发布 | 复用 | 在现有限额内接入模板/套图策略，明确局部重规划与风格锁关系 |
| Provider 配置、协议与模型能力适配 | 复用 | 不新增 renderer 直连、不替换已有密钥和请求边界 |
| 生图执行、参数覆盖、图片规范化、输出快照及溯源 | 复用 | 结果绑定统一目标，展示改变不重写产物 |
| 编辑规划、参考用途、分支记忆、蒙版/保护区、扩图、版本链 | 复用 | 修复输入与计划绑定、会话恢复，并补明确可用的基图来源上下文 |
| 持久调度、取消、恢复、指纹、回执、UNKNOWN 屏障 | 保留现有机制 | 适配新增输入时同步指纹/快照，不建立旁路执行链 |
| ZIP、长图与已有高级处理能力 | 保留 | 补采用关系、顺序和导出恢复入口，不取消现有下载/分层等能力 |

### 已经共用的调用链

当前普通规划与商品图片规划均进入 `executePlan → planStoryboard`，并非两套完全不同的 AI 系统。

- [配置与普通规划命令](../packages/backend/src/commands/projects.ts)：`createPlanningJob`、`applyPlanningConfigSnapshot`。
- [目标规划命令](../packages/backend/src/commands/product-image-planning-jobs.ts)：`createProductImagePlanningJob`。
- [共同规划执行器](../packages/backend/src/execution/job-plan.ts)：`executePlan` 内的 `base/makeInput` 组织商品上下文、模型、素材及研究选项。
- [规划 Agent](../packages/agent/src/planner.ts)：`planStoryboard/validatePlan` 负责工具、提示约束和结果校验。
- [素材组织](../packages/backend/src/execution/visual-assets.ts)：`assignImageHandles/selectVisionAssets/selectGenerationAssets/withGenerationAssetRoles`。
- [冻结输入](../packages/backend/src/execution/snapshot.ts)与[执行上下文](../packages/backend/src/execution/context.ts)：`createExecutionSnapshot/createExecutionContext`。
- [生成执行](../packages/backend/src/execution/job-generation.ts)：`executeGeneration`。
- [编辑执行](../packages/backend/src/execution/job-edit.ts)：`executeEditPlan/executeEditGeneration`，继续使用 `planImageEdit` 和现有审批/自动续接机制。

新工作流在这些既有链路前增加共享的输入汇合与目标适配，沿用其模型调用和资源处理。避免为新版页面复制一套上下文构造或模型请求代码。

### 不能仅靠接线解决的四处衔接

1. **目标规划与模板策略。** 目标分支目前显式使用 AI 模式，未传手选模板/套图约束；现有 MANUAL 模式还有模板/镜头唯一性规则。新增“目标 → 模板/镜头约束”的映射，按目标及批次适配原策略，保留模板合法性和视觉任务去重，不能简单删除校验来允许重复。多个 SKU 使用同类模板时仍隔离附件；套图数量、用途与现有需求冲突时，在提交前显示并确认。
2. **有效输入与补充说明。** 两页补充说明目前各自保存，AI 帮写结果不自动汇入目标规划；项目写入串行也不等于规划提交前已全部保存。抽出项目级准备草稿和提交协调器，复用现有保存函数、回执及版本校验，统一等待上传/项目/目录保存成功，再创建规划任务。
3. **三类保存不能混用。** 编辑中的草稿负责恢复未提交输入；用户可套用的规划配置历史负责复用制作配置；不可变执行快照负责重放与溯源。三者继续区分。现有用户配置历史未完整保存 SKU 目录、共图组和目标设置，需增量补全；旧历史缺项明确提示，不能从当前目录猜填，也不能覆盖当时的执行证据。
4. **编辑上下文继承。** 现有编辑规划已消费基图、本轮指令、标注、参考用途、分支记忆、事实及模型能力；尚未显式传入原生成提示词、完整模板约束、风格锁和禁止宣称。复用现有编辑上下文构造，并从可验证的基图来源增量提供相关约束。原图来源与本轮资料变更分别标识，冲突需明确处理；历史证据缺失时不以最新分镜冒充。无需为了继承约束重新运行整套规划，也不要求给编辑器复制完整规划工具目录。

### 真正需要重构的部分

- 用户可见的提交入口与输入汇合：一份有效配置，一次明确提交。
- 草稿生命周期：持久恢复、离开保护、取消回滚和提交前保存。
- 目标与方案的关系：删除、排序、重新规划、来源变化和确认范围一致。
- 结果组织：从“已有批次输出”补成“所有当前目标及其候选”，保留批次追溯。
- 编辑计划绑定与恢复：当前输入不能继续批准旧计划，既有持久轮次能续接。
- 采用关系、导出恢复、项目继续制作位置：少量增量持久数据，复用现有产物与导出执行。

这些变化不要求重建全局商品库、替换所有项目/分镜表、重写 Provider 或整体重写编辑器。数据结构调整围绕上述缺口做增量扩展；现有 SKU 目录、目标解析与输出冻结归属继续作为实现基础。

## 目标与范围

用户目标：上传商品图和参考图，完成配置，由 AI 一键规划图片，再生成图片，并能单独修改任意生成结果。

主流程收敛为：

**商品准备 → AI 图片规划 → 成图与修改**

保留 PixelMuse A 版黑白界面、真实图片色彩、候选堆叠、局部选区与蒙版语义。任务执行仍显示一行摘要，详细记录置于右侧抽屉。

本次“一键规划”指一次提交完成整套图片方案。规划后保留一次明确的生图确认；不把规划按钮悄悄变成规划与生图连续付费按钮。用户无需逐张选择技术模板、模型或编写提示词。

## 一、商品准备

### 页面与素材

主体为两个明确的素材区域，避免同一个上传框依赖隐藏的当前类型：

- 商品图：至少一张，作为商品外观依据，支持多角度、细节和不同规格。
- 参考图：可选，作为风格、构图、光影或排版参考；不得自动成为商品真值或已核验卖点。

保留拖拽、粘贴、资产库选图和电商参考采集能力。粘贴目标、上传进度及失败文件须明确；尚未完成上传的文件不能悄悄被下一次规划遗漏。

参考用途可以用一个简短说明表达。更细的逐图用途标签可后置，不作为首次规划的必填项。

### 配置

默认展开：

1. 商品名称、简短描述和用户提供的卖点；名称可使用草稿默认值，描述可补充。
2. 本次图片需求：主图数量、详情图数量；没有 SKU 时不要求建立目录。
3. 多规格商品可展开 SKU：名称、编码、属性、对应商品图、是否参与本次制作。共图只通过明确分组设置。
4. 平台、文案语言、比例与风格要求使用默认值并允许修改。

高级设置收起：推理/生图模型覆盖、候选数量、分辨率、提示词语言、商品保护模式、模板与套图约束、已核验事实及禁止宣称等。模型默认值从现有设置中心读取，显示简短当前配置摘要及修改入口。

必需条件应尽量少：有效商品图、至少一个图片目标、可用规划模型。允许先创建项目、整理素材，执行到对应阶段才校验需要的模型。SKU 图片需要相应规格的明确商品图绑定；缺项时直接定位该 SKU。

AI 推测出的规格、性能或卖点不能静默写入已核验事实；现有人工信息与 AI 建议必须可区分。

### 主按钮：AI 一键规划

点击后依次：

1. 等待上传和配置保存完成，保存失败则保留输入并停止提交。
2. 检查素材、图片目标、SKU 引用和模型；错误定位到对应字段。
3. 冻结本次输入版本与请求身份，创建规划任务。
4. 进入图片规划页，先显示明确的目标与规划状态。
5. 后台按现有限额分批处理，在完整有效结果发布后展示可审阅方案。

输入草稿需可恢复，阶段切换、折叠面板和重启不能清空用户未提交的要求。商品资料保存与调用模型仍是独立动作。

## 二、图片规划

### 一个统一入口

统一用户可见的规划提交入口，所有新制作使用一致的已保存资料、需求和结果归属。现有 AI、自选模板、套图及商品目标规划的内部策略、校验和执行能力优先保留，通过编排与输入适配接入；不直接删除旧规划执行分支，也不把现有模板/套图能力降级为一段自由文本。

AI、自选模板和套图都作为该流程的策略：

- 默认：AI 根据商品与需求安排画面。
- 指定模板：约束相关目标的表现方式。
- 指定套图：导入为可调整的目标与模板约束，明确用途映射和与原需求合并/替换的范围。

套图中无法自动确定的用途需用户确认，不能静默归类为 SKU 图。首次重构可先提供显式套图导入，避免保留第二个直接写入当前分镜集合的入口。

### 用户看到的内容

按主图、SKU 图、详情图分组展示卡片。每张卡片显示：

- 图片用途、顺序及关联规格。
- 画面标题、主要构图和商品呈现方式。
- 拟使用的文案及卖点。
- 关联商品图、参考图及必要的缺项/风险提示。

技术提示词默认收起；普通用户可以修改自然语言要求。

可进行的动作：调整方案、添加图片需求、取消图片需求、重做选中方案、更新受影响方案、重做整套方案。整套重做须说明手工修改与现有结果的处理方式。

必须区分：

- 取消需求：移除本次交付目标，数量随之更新，已有结果留在历史中。
- 重做方案：保留目标，创建新的画面方案。
- 重新生图：保留确认方案，新增候选结果。

### 主按钮：确认并生成

默认选择全部有效目标；允许只生成明确选中的目标。显示准确的画面数和候选总数，按每张画面的实际配置计算。不能把缺乏价格数据的估算显示为确定费用。

例如：5 张主图、6 个 SKU 明确共用 3 组图片、8 张详情图，每个目标生成 2 个候选，则是 16 个画面、32 张候选。

确认作用于本次选中目标的当前方案版本。未选中目标缺项或待更新时，应保留可见提示，不能仅因无关目标不完整而阻断有效目标；但项目级活动任务与 UNKNOWN 请求保护仍需遵守，不能以拆目标方式绕过。

## 三、成图与修改

### 按图片目标组织

当前目标始终显示卡片，无论是否已经成功生成图片。主图、SKU 图、详情图仍分组展示。

每个目标分别展示方案有效性、执行状态和采用状态，避免把所有含义塞进单个状态字段。

- 方案：待规划、待确认、已确认、待更新。
- 执行：未开始、排队中、生成中、失败、待核实；以持久任务为准。
- 采用：尚未采用、已采用。

已有采用图片的目标可以同时进行新候选生成。新任务失败不删除已有图片或采用关系。

同一目标的候选继续堆叠显示，支持左右切换、放大比较和历史版本查看；批次用于追溯，不作为默认组织依据。

### 每张结果的操作

- 修改这张：打开以该图为基图的独立编辑工作区。
- 再生成：按当前明确方案创建新候选，提交前显示实际参数和范围。
- 采用此图：持久记录为当前目标的采用版本；可以替换。
- 下载：保留单图下载。

一张目标可以有多个候选和编辑版本，默认采用一个主版本；更多图片应通过增加图片目标或明确选择备用图表达。

### 单张修改流程

1. 点击“修改这张”，打开大图与简短修改输入区。
2. 输入修改要求，例如“背景换成浅灰色，保留商品颜色和文字”。
3. 按需画选区/蒙版、加入本轮参考图；模型与参数放在高级设置。
4. 复用现有编辑规划、审阅确认与生成链，保持当前自动执行/审阅策略及其配置语义；简化入口文案，不擅自改变默认付费执行行为。
5. 修改期间显示任务状态；完成后并排或切换比较原图与修改图。
6. 用户可“采用此版本”或继续修改，原图和版本关系保留。

执行前冻结基图、输入、参考图、选区及参数。预览计划后如输入发生变化，必须重新规划或明确使用旧计划，不能把新输入和旧 turn 混用。

离开页面或重启后应恢复已有编辑轮次及任务状态。结果待核实时显示核实入口，不自动重新发起付费请求。修改一张不重新规划整套，也不自动替换其他目标。

### 下载与定稿

本次不增加独立交付页面。在成图页提供：

- 下载当前图片。
- 下载已采用图片。
- 自选图片批量下载。
- 详情图按保存的顺序生成长图。
- 导出记录及再次下载入口。

采用关系和详情顺序持久保存；普通下载勾选仍可保持临时状态。未采用全部目标时允许明确的部分下载，并显示缺项数量。

## 四、数据与执行边界

这是逻辑职责划分，不要求立即建立全新的商品库或多个服务。

| 对象 | 责任 |
| --- | --- |
| 项目 | 本次制作的名称、归档状态、导航续接信息与业务摘要 |
| 商品资料 | 描述、事实约束、素材角色、SKU 身份及来源版本 |
| 图片需求 | 稳定目标身份、用途、规格关联、顺序、是否参与及本次风格要求 |
| 画面方案 | 绑定输入版本的构图、文案、引用和确认状态 |
| 任务 | 持久执行、取消、恢复、请求去重及未知状态核实 |
| 成图与编辑版本 | 不可变产物、基图与父子版本、冻结用途和规格证据 |
| 采用与导出记录 | 当前需求采用哪个产物、详情顺序及已生成交付文件 |

关键规则：

1. 图片目标有稳定身份，顺序调整不改变身份；数量与目标集合不能各自维护互相矛盾的真相。
2. 规划绑定实际消费的资料/需求版本或指纹。首次可采用保守的相关内容失效规则，再细化影响范围；项目改名等无关变更不应使所有画面失效。
3. 商品事实、实际引用或规格改变后，相关当前方案需要更新。已生成结果保留原来源，当前需求是否沿用旧图由用户明确决定。
4. 已提交任务使用冻结输入，后续保存不改写在途请求；新输入只作用于后续明确请求。
5. 确认方案和创建任务之间校验版本；查询或恢复相同意图不能被当作新付费请求。
6. 保留任务指纹、请求账本、UNKNOWN 屏障、PRODUCT_TRUTH/PIXEL_PROTECTED、模板校验及输出稳定身份。
7. 项目进度依据当前目标的有效方案与采用结果派生，不再仅以存在素材/分镜/输出推断完成。

继续使用现有 Electron + React + utilityProcess Backend + SQLite。契约仍从 TypeBox schema 定义，renderer 不直接访问 Provider 或数据库。

## 五、实施顺序

### 实施前：能力与上下文基线

- 建立配置字段及上下文消费者映射，列明 AI、自选模板、套图、商品目标和单图编辑的实际能力。
- 记录现有相关测试与合成输入样例，保留当前未提交修改及已发布升级基线。
- 确定新增输入适配、共享发布逻辑和少量持久关系的边界；先验证各策略能进入统一目标体系，再收起旧的可见提交入口。

### 第一批：统一准备与规划

- 复用现有上传、素材选择、配置字段与保存 hooks，按职责整理页面；高级选项保持可访问，不因移位丢失。
- 项目可先作为草稿建立，阶段执行前检查对应模型。
- 将旧 AI/模板/套图入口收敛到统一需求与规划流程。
- 持久保存草稿，等待上传/保存完成后再提交规划。
- 修正套图取消回滚、删除目标与数量一致性。
- 建立规划输入版本、变更失效与确认规则。

### 第二批：目标驱动生成和选片

- 按目标展示包括失败/未生成在内的全部卡片。
- 支持确认当前有效目标并批量生成，显示准确候选总数。
- 保留候选堆叠、再生成、任务摘要和抽屉。
- 增加采用版本及目标完成度。

### 第三批：单图修改与恢复闭环

- 精简编辑默认界面，保留高级编辑能力。
- 绑定编辑输入与计划，修复旧计划误执行问题。
- 恢复待确认/执行中/待核实的编辑轮次。
- 修改后比较、继续修改、采用新版本。
- 持久保存详情顺序、导出记录及项目继续制作位置。

每批完成相关构建和专项真实 Electron 操作验证。按实际改动选择测试，不自动重跑全套或重打包。发布包与 Git 提交另按用户明确要求执行。

## 六、旧项目与验收

迁移采用可验证、可回滚失败的增量数据库升级，具体 schema 版本在实施时确定。

- 保留项目、素材、任务、回执、成图和编辑关系，不复制 legacy 数据或凭据。
- 旧式分镜可以转换为明确标注的未分类目标，保留可继续查看和操作的路径。
- 不根据图片外观或旧提示词补造 SKU 归属；用户需要时显式归类。
- 已冻结的输出来源不随目录变更改写。
- 不自动把最新图设为用户已采用版本；提供明确的首次选片动作。
- 既有模板与套图能力通过统一需求入口保留，迁移期间不能再让两个提交入口隐式修改同一方案。

复用验收先于页面验收：

- 对现有配置逐项检查保存、重开、历史配置套用和实际请求消费，不能只验证新页面存在同名输入框。
- 使用隔离合成数据覆盖 AI、自选内置/用户模板、套图、商品主图/SKU/详情目标、单图编辑各策略。比较结构化输入、实际消费的模板/素材及输出归属，保留既有事实约束、风格和参数语义；不要求含随机标识或时间的请求逐字相等。
- 核对调用次数及付费边界：已有意图恢复不能增加外部请求；局部修改不能意外重新规划整套；不通过另建调用链避开旧约束。
- 已有专项测试继续作为回归依据，新增检查聚焦改变的入口、上下文适配和状态转换。

专项验收至少覆盖：

1. 只上传商品图，无参考图、无 SKU，完成规划→生成→单张修改→下载。
2. 商品图与参考图同时上传，确认角色隔离和规划引用。
3. 多 SKU 独立图与显式共图，数量、附件和输出归属正确。
4. 上传中或保存失败时点击规划，不能使用遗漏/旧输入提交。
5. 删除、添加、排序目标后，数量、确认与生成资格一致。
6. 商品事实或 SKU 图片改变后，相关方案待更新，历史图片不被改写。
7. 部分生成失败时目标仍可见，可安全恢复，已有采用图保留。
8. 编辑预览后改输入、切阶段、重启，执行内容与恢复状态正确。
9. UNKNOWN 不能通过换页面、目标或修改输入绕过；完成回执可本地恢复。
10. 采用、详情顺序、导出记录及继续制作位置重开后保持。
11. 旧无分类项目和已有编辑版本升级后可读取，不编造归属。

假 Provider 验收用于行为和恢复正确性，不代表真实模型的商品一致性、画面质量或安装器升级质量已验证。
